## The problem

Training a model is not enough to understand it. Data selection, evaluation splits and serialization affect whether the result means what it appears to mean. These repositories work through those foundations with small, inspectable examples.

## Architecture of the regression exercise

The Advertising example reads CSV data through pandas. TV, radio and newspaper spending become features and sales becomes the prediction target. A fixed random seed makes the train/test split repeatable. Scikit Learn fits a linear regression, joblib saves the fitted model, and the script reloads it before predicting on test rows.

Evaluation prints mean squared error and R squared and plots actual against predicted sales. Separate labs work through cost functions and gradient descent. The Python_learning repository supports this work with examples of array indexing, broadcasting, dataframe joins, grouping and missing data handling.

## The important constraint

The regression script explicitly uses 20% of the data for training and 80% for testing. That is the implemented split, even though a reader might expect the reverse. It leaves less data for fitting and is a useful reminder to inspect evaluation code rather than infer a workflow from familiar names.

## Result and next steps

These are learning repositories, not a deployed prediction API. The saved model round trip makes artifact loading part of the exercise, but the available code does not establish production accuracy or operational readiness.

Next I would compare against a simple baseline, use validation across multiple data splits to understand split sensitivity, add checks for the expected feature schema and persist model metadata alongside the artifact. Evaluation on representative datasets would come before claiming the model generalizes beyond this exercise.
