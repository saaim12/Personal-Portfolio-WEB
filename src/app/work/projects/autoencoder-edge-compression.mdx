## The problem

Remote sensors have limited memory, power, and network capacity. I built an autoencoder workflow to explore compact representations of sensor data, with encoding on the device and reconstruction on a server.

## What I built

I trained an autoencoder and tuned the latent representation used to carry sensor information. I converted the encoder for TensorFlow Lite Micro inference on an ESP32 and exposed the decoder through a Flask API on AWS EC2. S3 integration supported encoded payload handling.

The device and server share a model contract. Input scaling, latent dimensions, and compatible encoder and decoder versions must remain aligned for reconstruction to work.

## Engineering decisions

**Split the model across device and server.** The device runs the encoder while the server handles decoding. This keeps the reconstruction workload off the device but makes artifact compatibility part of deployment.

**Treat reconstruction quality as a requirement.** A smaller latent representation is useful only if the reconstructed signal retains the information the application needs. Evaluation should include important changes in the signal alongside aggregate error.

**Measure transmission savings directly.** A compact representation does not automatically establish lower energy use. Encoding cost, payload serialization, and radio transmission all contribute to the result.

## Result and next steps

The project connects model training, device inference, and cloud reconstruction. It demonstrates the deployment interfaces involved in running parts of one model across different environments.

My next steps would be to compare serialized payload sizes with a simple compression baseline, measure reconstruction quality on representative sensor data, and record device memory and energy use. Those measurements would determine whether this approach suits a particular sensor workload.
